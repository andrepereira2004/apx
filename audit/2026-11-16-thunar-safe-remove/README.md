# Thunar safe removal and device notifications — 2026-11-16

Owner requests safe unmount/eject in Thunar and notifications on storage-device insertion/removal, using the existing visual notification system. This is the disposable physical pilot, with explicit authorization to change the system.

Design: preserve native Thunar actions for normal devices; add a Desmontar com segurança context-menu action and eject affordance for the two admitted Host file-bridge USB volumes. An unprivileged helper calls the existing peer-authenticated Host v3 broker with a typed media.unmount request containing only one allowlisted UUID. The broker retains its current sandbox/capabilities and delegates through a root-only local Unix socket to the existing Host mount service. No raw device or arbitrary path/command is accepted. The media service rechecks device identity under its mount lock, uses ordinary umount (no force/lazy), and suppresses automatic re-mount for the same physical diskseq until unplug/replug. Read-only .ejected metadata is visible through the existing bridge. Busy failures are reported as errors, never successful removal notifications.

Notifications: an Environment-local GIO volume observer detects removable storage insertion/disconnection; bridge mount state adds safe-removal events. It uses notify-send through the existing common Mako cards, in Portuguese, with a USB icon. Connection/mount and safe-removal/physical-unplug are deduplicated. Existing devices at observer startup do not create artificial arrivals. udiskie notifications are disabled to avoid duplicate/English cards. The shell starts the observer for new sessions; active services will be reloaded after backup. Native device rows suppressed by the Host ejected marker stay hidden until reconnect.

Recovery: backups preserve installed broker/contract, media helper, Environment assets and native Thunar binaries. Existing safe-removal state is runtime-only under /run; restoring helpers and clearing only the named media marker restores automatic mounting. Planned validation includes native build/patch replay, unit cases for busy devices/reconnection/admission/deduplication, a real blocked unmount with a temporary open file, and the actual Thunar menu callback followed by restoration of the mount for the owner.
